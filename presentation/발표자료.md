# 발표 자료

## 0. 이름, 프로젝트 이름
- 이름: 최현호
- 프로젝트 이름: OLED 소자 Luminance 예측 MCP 서버 (`oled-luminance`)

## 1. 뭐가 불편했나
OLED 소자 설계 연구원이 새로운 소자 조합을 검토할 때마다, 직접 소자 조합 하나를 검토하는 데 5일 정도 걸리는 반복 작업이었다.

## 2. 뭘 만들었나
Host/Dopant 물성치와 구동조건(전압, 전류밀도)을 입력받아 CatBoost 회귀 모델로 Luminance(cd/m²)를 즉시 예측하는 MCP 서버를 만들었다. `predict_luminance` Tool 1개를 제공하며, Synthetic Dataset 생성 → CatBoost 모델 학습 → 추론 모듈 → HTTP 기반 로컬 전용 MCP 서버까지 전체 파이프라인을 구현했다. 실제 동작을 눈으로 확인할 수 있는 데모 웹페이지(`demo/app.py`)도 함께 만들었다.

## 3. AI한테 맡긴 것
Phase 1~4 전부(Synthetic Dataset 생성, CatBoost 모델 학습, Inference 모듈, MCP 서버 개발)를 AI(Claude Code)에게 맡겼다. 이후 전송 방식을 stdio에서 HTTP로 바꾸는 리팩터링과, catboost import 위치를 워커 스레드에서 메인 스레드로 옮겨 응답이 멈추는 버그를 재현·수정하는 디버깅까지 포함해서, 사람이 직접 코드를 작성한 부분은 없다.

## 4. 됐는지 어떻게 확인했나
- `data/data.json`에 데이터 10,000건 생성 확인
- `models/luminance_model.cbm` 파일로 CatBoost 모델 저장 확인
- `inference/predict.py`의 `predict_luminance()`가 샘플 입력에 숫자 값을 반환하는지 확인
- MCP 서버(`http://127.0.0.1:8090/mcp`) 실행 후 `predict_luminance` Tool을 샘플 입력으로 호출해 `luminance_cd_m2` 필드 응답 확인, 필수 필드 하나를 빼고 호출해 `VALIDATION_ERROR` 응답도 확인
- `claude mcp list`로 Claude Code가 서버에 정상 연결되는지 확인
- `demo/app.py` 데모 페이지에서 실제 MCP HTTP 프로토콜로 Tool을 호출해 "파싱된 입력 → 원본 MCP 응답 → 자연어 요약" 전 과정이 눈으로 보이는 것을 확인

(단, 데이터가 완전 무작위(Synthetic)로 생성되어 예측값 자체의 물리적 신뢰성은 검증 대상이 아니다 — MCP 파이프라인이 정상 동작하는지만 확인했다.)
